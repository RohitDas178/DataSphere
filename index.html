Step 02: Duplicate Records Deduplication

What can you do in this step?

Identify identical redundant records across your dataset. You can keep the first occurrence, keep the latest occurrence, or choose to retain all duplicates untouched.

Why should you do this?

Duplicate records artificially inflate metric counts (e.g. over-counting sales or patients), distort variances, bias correlation metrics, and cause severe overfitting in analytical models.

Deduplication Configuration

Select how duplicate records should be treated.

All Available Deduplication Methods:
1. Keep First Occurrence Recommended

Scans chronologically from row 0 downwards. Keeps the original encountered instance of identical rows and discards later duplicates.

Dataset Impact: Decreases $N$ by duplicate count. Eliminates artificial frequency bias while preserving original chronological baseline.
2. Keep Last Occurrence Alternative

Scans backwards from the bottom of the dataset. Keeps the most recently inserted revision of duplicate rows and discards earlier ones.

Dataset Impact: Decreases $N$ by duplicate count. Preserves newest state in CRM or event-log updates; may invert chronological sequence.
3. Retain All Duplicates Non-Destructive

Leaves all identical rows in the dataset completely unmodified.

Dataset Impact: Zero reduction in $N$. Keeps metric counts inflated if duplicate entries were unintentional data collection errors.

Step 03: Missing Value Imputation & Handling

What can you do in this step?

Handle null, empty, or unrecorded cells using Smart Auto-Imputation (Median for numerical, Mode for categorical), statistical Mean, Median, Mode, constant values ("Unknown"/0), or row elimination.

Why should you do this?

Missing cells cause formulas to return NaN, exclude data points from graphs, and introduce selection bias. Imputation preserves sample volume while safeguarding the underlying probability distribution.

Scanning for missing values...
Scanned

Missing Values Strategy

Select your preferred statistical imputation technique.

All Available Missing Value Imputation Methods:
1. Smart Auto-Impute Recommended

Applies Median to numeric metrics and Mode (most frequent category) to text attributes automatically.

Dataset Impact: Preserves 100% of rows ($N$ unchanged). Neutralizes skewness in numeric columns while classifying text nulls into the dominant category.
2. Median Imputation Robust

Replaces missing numeric values with the 50th percentile. Highly resistant to extreme outlier spikes.

Dataset Impact: Keeps distribution center stable even on skewed data. Slightly shrinks column variance without distorting median.
3. Mean Imputation Parametric

Fills empty cells with the arithmetic average ($\mu$). Best suited for symmetrical bell-curve distributions.

Dataset Impact: Preserves the sample mean exactly; depresses standard deviation ($\sigma$); can pull distribution if high outliers exist.
4. Mode (Most Frequent) Categorical

Replaces nulls with the category holding highest frequency count in that attribute.

Dataset Impact: Preserves sample volume. Inflates class dominance of top category; may underrepresent minority groups.
5. Constant ("Unknown"/0) Explicit

Fills text nulls with "Unknown" and numeric nulls with 0. Used when missingness is informative.

Dataset Impact: Adds an explicit "Unknown" slice in charts; for numbers, adding zeroes can drag averages down significantly.
6. Drop Incomplete Rows Aggressive

Deletes any entire record containing one or more null values (Listwise Deletion).

Dataset Impact: Decreases total row count $N$. Guaranteed 100% authentic observations, but risks losing statistical power and introducing selection bias.

Step 04: Outliers & Statistical Anomalies Treatment

What can you do in this step?

Detect extreme data spikes using IQR (Interquartile Range) and Z-Scores. Treat them via Winsorization/Capping (5th & 95th Percentile), row filtering, or choose to retain them untouched.

Why should you do this?

Extreme anomalous values drastically pull arithmetic averages, wildly inflate variance metrics, and distort regression curves. Winsorization neutralizes extremes without deleting valuable records.

Scanning for statistical outliers...
Scanned

Outlier Management Method

Select how extreme numerical points should be regulated.

All Available Outlier Treatment Methods:
1. Winsorization / Capping Recommended

Clamps extreme low values to 5th percentile ($P_{05}$) and high spikes to 95th percentile ($P_{95}$).

Dataset Impact: Preserves 100% of rows ($N$ untouched). Neutralizes distortive spikes while keeping all genuine records intact.
2. 1.5x IQR Boundary Rule Robust Filter

Deletes any row falling outside $[Q_1 - 1.5 \times IQR, Q_3 + 1.5 \times IQR]$. Non-parametric standard.

Dataset Impact: Reduces row count $N$. Restores symmetry to skewed distributions; risks dropping valid high-value customers.
3. Z-Score > 3.0 Filter Parametric

Deletes rows with $|Z| > 3.0$ (more than 3 standard deviations away from the mean $\mu$).

Dataset Impact: Removes extreme tail anomalies (top 0.3%). Best on normal distributions; can be distorted if initial outliers are massive.
4. Keep Outliers Untouched Preservation

Leaves all numerical values raw and unmodified.

Dataset Impact: 0 rows modified. Averages and chart axis scales remain stretched by extreme spikes. Ideal for fraud/anomaly research.

Step 05: Text Sanitization & String Standardization

What can you do in this step?

Strip invisible leading/trailing whitespace, harmonize irregular capitalization across text columns, and normalize boolean flag indicators (yes/no/1/0 -> True/False).

Why should you do this?

Without normalization, groupings treat "USA", "usa", and " USA " as three disjoint categories. Standardizing text guarantees clean grouping, accurate counts, and flawless category legends.

String Standardization Settings

Configure casing and format normalization.

All Available Text Normalization Methods:
1. Trim & Title Case Recommended

Strips whitespace and capitalizes the first character of each word (" new york " $\rightarrow$ "New York").

Dataset Impact: Merges fragmented category duplicates into clean unified labels. Optimal for proper nouns, cities, and departments.
2. Trim Whitespace Only Preserves Case

Removes padding spaces while leaving original character capitalization untouched.

Dataset Impact: Fixes spacing defects while preserving mixed-case codes (e.g. "iPhone", "MacBook").
3. Trim & Lowercase NLP / Web

Strips spaces and converts all letters to lowercase ("NEW YORK" $\rightarrow$ "new york").

Dataset Impact: Aggressive normalization. Ideal for email addresses, search tokens, and NLP pipelines.
4. No Text Modification Raw Input

Leaves string values exactly as formatted in the raw uploaded file.

Dataset Impact: Risk of splitting a single real-world category into multiple chart items due to differing casing.
